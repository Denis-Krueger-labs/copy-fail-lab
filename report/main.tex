\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

This report documents the controlled analysis, reproduction, detection,
mitigation, and retesting of CVE-2026-31431, commonly referred to as
\emph{Copy Fail}.

The research is conducted within an isolated laboratory environment and
focuses not only on demonstrating the vulnerability, but on understanding
the affected Linux kernel functionality, identifying observable behaviour,
developing a custom detection strategy, evaluating a compensating control,
and comparing those results with vendor-provided mitigations and patches.

Evidence is collected throughout the experiment and preserved separately
from the analytical report. Raw evidence is retained privately, while
sanitized artifacts intended for public release receive their own integrity
verification before being added to the repository.

\section{Evidence Overview}

Experimental evidence is maintained separately from the analytical report
under the repository's \code{evidence/} directory.

Each experimental phase receives its own evidence directory containing the
relevant command output, screenshots, integrity manifests, and other
supporting artifacts.

The report and evidence therefore serve different purposes:

\begin{itemize}

    \item
    the report explains the methodology, observations, interpretation, and
    conclusions;

    \item
    the evidence directories preserve the artifacts supporting those
    conclusions.

\end{itemize}

Where sanitization is required for public release, the original artifact is
preserved privately before modification.

The public workflow is:

\begin{lstlisting}
raw evidence
    |
    v
private integrity verification
    |
    v
preserved private copy
    |
    v
sanitized public artifact
    |
    v
public integrity verification
    |
    v
Git repository
\end{lstlisting}

This prevents the sanitized repository artifacts from being mistaken for the
original raw evidence while still providing integrity verification for the
public dataset.
